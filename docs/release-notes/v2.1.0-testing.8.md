## Notable Changes

Everything since v2.1.0-aarch64.4. A testing build: most of it is
reverse-engineering work that replaces recompiled game code with native
code, which should look and play the same while using less CPU.

### Performance (less CPU, so less heat and battery on handhelds)
- **The render thread waits for the GPU instead of spinning.** When the
  game waits on a GPU fence, the thread now sleeps until the GPU signals.
  Odin 2, uncapped: render-thread CPU 2.05 → 1.63 ms a frame, 1% lows
  59-60 → 65 fps, p99 frame time 13.8-14.1 → 12.5 ms. At the 30 fps cap the
  game rarely waits, so little changes there.
  Setting: `skate3_native_fence_wait` (on).
- **The game's job threads wake only when there is work.** The game used to
  wake every worker thread each time it queued a job; most woke to find
  nothing. Odin 2 at 30 fps: job-thread CPU −6%.
  Setting: `skate3_native_job_wake` (on).
- **Frustum culling runs as native code** (the per-object visibility test
  against the view, occluders and a size cutoff). It matched the game's
  own result on every one of ~750,000 calls tested. Odin 2 at 30 fps:
  job-thread CPU −5% more.
  Setting: `skate3_native_cull_replace` (on; `off` runs the game's code).

### Characters
- **The native renderer reads each character's pose from the game's own
  data** (the "skeleton store"), for skaters and now pedestrians too,
  instead of matching bone data by content. Poses are the same as before;
  this removes guesswork behind earlier body-part bugs.
  Settings: `skate3_native_render_scene_skeleton`,
  `skate3_native_render_scene_skeleton_lw` (both on).
- **Native pose and job-system code:** the bone gather, the matrix packing
  for the GPU, the pedestrian bone writer and the job workers' loop, wake-up
  and waits now run as native code (bit for bit the same results where they
  compute something).
  `skate3_native_replace_all = off` runs all of the game's original code
  instead, for comparison.

### Known issues
- **KI-127 (new):** at uncapped frame rates (~300 fps), a district load
  after a teleport can crash (3 in 26 runs on the Odin 2). The default
  30 fps cap is not affected as far as tested.
- **KI-125 (cause found, still open):** for one frame after a replay jumps
  to a new time, the skater's hair and shirt can be drawn detached. The
  cause is a race on the cloth buffers after a seek.

### Scenario harness and tooling
- **Guest CPU profiler:** the `profile` verb and
  `tools/harness/profile_report.py` rank game functions by CPU per thread,
  job threads included.
- **Per-frame times:** `frametime_report.py` (lows, jitter, A/B, the log
  lines from the worst frames); `scenario_cvar_ab.sh` runs alternating A/B
  sets of a setting.
- **Frame dumps:** the `video` verb and `play_reel video = true` record
  every frame.
- **Career tools:** set board sales, cross milestones, and complete
  challenges with their rewards from the harness (`career`, `results`
  steps).
- **Headless Windows runs** start in a hidden window with the sound muted.
- `tools/odin2_screen.ps1` shows the Odin 2's screen on the PC, with the
  controller passed through.

### Documentation
- `docs/re/`: the reverse-engineering notes. Function and structure names
  carried over from Skate 2, the career and board-sales model, the
  characters' render path, culling, and the catalog of native replacements
  (`docs/re/replacements.md`).
