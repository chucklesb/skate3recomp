## Notable Changes

### Fixes
- **Menus were slow because the game's own renderer drew the whole scene
  behind them.** Screens that show skater portraits (Edit Skaters, Create-a-
  Skater, parts of My Replays) let the game's original renderer run so the
  portraits get drawn, and a size mix-up meant it also redrew the entire
  game world every frame. Now only the portraits are drawn that way. On the
  Odin 2, Pause > Edit Skaters went from 29 fps (worst frame 100 ms) to
  52 fps (worst 26 ms), uncapped. The skater photo saved when you leave
  Create-a-Skater still updates correctly. If a menu shows something wrong,
  `skate3_native_render_scene_portrait_scene_band = true` restores the old
  behaviour.
- **Photo challenges showed no photo** on the final showcase screen. The
  photo is now taken from the native renderer's frame at the moment of the
  shot.
- **Sharper photos and reel thumbnails.** Challenge photos and saved reels'
  thumbnails were noticeably soft on the Odin 2; they are now downscaled
  with a filter matched to the screen resolution.

### Scenario harness and tooling
- **Emulated-pass census:** `native_render_pass_census` counts which of the
  game's own draws still run under the native renderer, per screen;
  `tools/harness/census_report.py` summarises a run. Scenarios
  `census_smoke.toml` and `census_menus.toml`.
- **Create-a-Skater portrait check:** `scenarios/cas_portrait.toml`
  (generated by `tools/harness/gen_cas_portrait.py`) puts a helmet on and
  takes it off, checking the team portrait each time; `--only on|off`
  checks the saved photo across a restart.
- **Windows live sessions and Odin 2 recordings:** `tools/harness/win_live.ps1`
  starts the Windows build in live mode; `tools/harness/odin2_record.ps1`
  records the Odin 2's screen with scrcpy.
